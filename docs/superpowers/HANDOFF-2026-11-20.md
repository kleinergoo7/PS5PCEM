## 5. Technical state — how the PS4 path works now

### 5.1 Pipeline flow

1. `src/hle/libs/ps4_title_stubs.zig` — `sceGnmSet{Ps,Vs}Shader` imports capture guest shader pointers and register real GCN blobs. Task 6 fixed the old "first import, partial pair" bug so registration happens against the pair the draw binds.
2. `src/ps4_mode/gcn_blob.zig` — parses real `OrbShdr\x07` blobs; `parse()` / `isaBytes()`. Real blobs were found in eboot (`0x50a820..0x50bdc0`) and ps4heap.
3. `src/ps4_mode/gcn_decode.zig` — GCN word decoder; now handles the real VS's SOPK/VOP2/VOP1/SMRD/EXP families after the last repair.
4. `src/ps4_mode/gcn_translate.zig` — program-keyed registry (`registerShaderFor`, `translatedGraphicsFor`), per-stage options, dynamic scalar slots, UV coordinate location, etc.
5. `src/hle/libs/gnm_compat.zig` — PS4 submit: publishes per-DCB resource captures from `gcn_resources.capture()`, sanitizes PM4 via `pm4_sanitize`, funnels into shared `agc_submit.submitDeviceStream`, triggers video-out flip.
6. `src/vulkan/backend.zig` — PS4-gated draw seam `wantsPs4FixedColorDraw` → `drawPs4FixedColor` (name is legacy), which now:
   - gets per-draw resources from `gcn_resources.nextDrawResources()`,
   - stages the PS texture via `stagePs4GraphicsSampledImage` at binding 1/element 1,
   - stages vertex data when applicable,
   - calls `drawGraphicsShadersWithModules` with translated SPIR-V and dynamic scalars,
   - presentation via scanout buffer + shared flip path.
7. First-frame dump: `PS5_CAPTURE_FIRST_FRAME=1` makes Vulkan write `out/first-frame.ppm` (P6, 1920×1080).

### 5.2 The real VS is now fully understood (commit `fd6fc39`)

Real VS ISA = the 16-dword blob historically called `ps_words` in `gcn_real_blob_test.zig` (classification: exports POS0 `0x0c` / PARAM0 `0x20`). Word-by-word decode from the agent's report:

| # | word | instruction | semantics |
|---|---|---|---|
| 0/1 | `beeb03ff` / `00000007` | SOP1 prolog literal | shader marker |
| 2 | `36020081` | VOP2 0x1b `v_and_b32 v1, 1, v0` | `v1 = 1 & v0` |
| 3 | `34020281` | VOP2 0x1a `v_lshlrev_b32 v1, 1, v1` | `v1 = v1 << 1` |
| 4 | `360000c2` | VOP2 0x1b `v_and_b32 v0, -2, v0` | `v0 = v0 & ~1` |
| 5 | `4a0202c1` | VOP2 0x25 `v_add_i32 v1, -1, v1` | `v1 = -1 + v1` |
| 6 | `4a0000c1` | VOP2 0x25 `v_add_i32 v0, -1, v0` | `v0 = -1 + v0` |
| 7 | `7e020b01` | VOP1 0x05 `v_cvt_f32_i32 v1, v1` | signed int→float |
| 8 | `7e000b00` | VOP1 0x05 `v_cvt_f32_i32 v0, v0` | signed int→float |
| 9 | `7e040280` | VOP1 0x01 `v_mov_b32 v2, 0.0` | z=0 |
| 10 | `7e0602f2` | VOP1 0x01 `v_mov_b32 v3, 1.0` | w=1 |
| 11/12 | `f80008cf` / `03020001` | EXP POS0 | `POS0=(x,y,0,1)` |
| 13/14 | `f800020f` / `03030303` | EXP PARAM0 | `(1,1,1,1)` |
| 15 | `bf810000` | SOPP `s_endpgm` | end |

So Terraria's VS builds a fullscreen quad purely from `VertexIndex`:
`x = ((v0 & 1) << 1) - 1`, `y = (v0 & ~1) - 1`, then int→float. No memory load; the previously injected MUBUF was a guess and was removed. Dumped SPIR-V confirms `OpLoad gl_VertexIndex` → bitwise/shift/add/int-to-float → `OpStore gl_Position`.

### 5.3 The current, precise blocker (PS constants)

The PS is the *other* real blob (historically `vs_words`, exports MRT0 and contains an image sample). Its ISA includes `s_load_dwordx4 s0, s[2:3]` and `s_buffer_load_dwordx4` loads. In every captured DCB so far:
- pixel `USER_DATA[2:3] == 0/0` (only indices 4, 6, 8..15 are written),
- so the constant-buffer pointer is null,
- `src/vulkan/backend.zig::ps4GraphicsScalars` still feeds **heuristic** values (grouped by producer PC: V# words, zero origin, 0.25 steps),
- the computed sample coordinate resolves to a black texel,
- `first graphics draw: readback colored_pixels=0` before and after the VS repair.

The running subagent is investigating whether the real constants exist anywhere in guest memory/other DCBs. If they do not, a correct first frame is impossible without fabricating shader input — explicitly forbidden — and the honest final status is BLOCKED.
